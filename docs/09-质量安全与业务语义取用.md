# 阶段 09：质量/安全 + 业务语义取用（服务的骨架成型）

## 背景思考

用户明确了项目定位：不只是"随机吐 ip"，而是**按业务语义、保证质量、筛选安全代理**的
代理分发服务。免费源不稳定、不安全（透明代理/篡改），这些差异要在后台消化掉，
业务方只表达"需要什么样的代理"。

## 完成内容（分层推进）

### L2 质量与安全校验
- **模型升级** `model/proxy.py`：新增 `latency_ms`（延迟）、`score`（信任分）、
  `tampered`（是否被篡改）；`create_from_json` 向后兼容老数据（缺字段用默认值）。
- **探针模块** `helper/probe.py`：两个安全/质量探针，共用"走代理 vs 直连对照"设施：
  - `check_anonymity`：走代理访问 `api.ipify.org`，比对"目标看到的 IP"vs"代理声称 IP"。
    不一致 → 透明代理（泄露真实 IP）→ 打 `transparent` 标签。
  - `check_tamper`：走代理和直连都 GET `example.com`（内容极稳），比内容哈希。
    不同 → 代理篡改/注入 → 打 `tampered=True`。
  - 延迟测量：验证时记录 TTFB。
- **check.py 集成**：存活验证通过后做安全/质量探测（**只打标签，不参与淘汰**——
  探针偶发失败不能误杀好代理）。新增 `probe_safety` 开关（测试关闭，避免联网）。
- **信任分**：成功 +1 / 失败 -1（累计，不归零，反映长期稳定性）。

### L1 存储：Redis 分桶
- `RedisPool` 新增索引 set：`use_proxy:cn` / `use_proxy:global` / `use_proxy:safe`
  （匿名+未篡改），配合原有 `use_proxy:https`。
- **一致性策略**：索引"尽力同步"——`put` 增删索引；`get` 取到候选后**二次校验**属性，
  过期索引不影响取用正确性。`count()` 返回各桶规模。

### L3 智能取用
- `ProxyService.get(need, https, security, quality, fast)`：按业务条件粗筛一批候选，
  信任分加权挑选（越稳越优先）。`get_many()` 提供候选。
- `pop(https, need, security)` 消费式。

### L4 取用策略模块化（与加源同构）
- `strategy/base.py`（BaseStrategy）+ `strategy/manager.py`（自动扫描 strategies/ 目录，
  按 name 分发，未知 mode 回退 random）。
- 三个策略：`random`（加权随机，默认）/ `sticky`（同 session 复用同代理，死了才换）/
  `rotate`（尽量不重复、轮流给）。
- **加新策略 = 在 strategies/ 放一个文件，零侵入**。

### API 业务语义化
- `/get?mode=&need=&type=&security=&quality=&fast=&session=`：由 StrategyManager 分发。
- `/pop?type=&need=&security=`、`/count`（分桶统计）、`/strategies`（列出策略）。

## 技术决策及理由

1. **探针只打标签不判生死**：探针依赖外部接口（ipify/example.com），偶发失败很正常；
   若参与淘汰会误杀好代理。安全是"标签"，存活是"生死线"，两者分开。
2. **分桶用"索引+二次校验"而非强一致**：代理属性会变，强同步复杂易错；
   索引加速候选、二次校验保证正确，简单且够用。
3. **策略与加源同构**：统一"接口 + 目录扫描 + 可插拔"的扩展心智模型，
   未来任何新取用需求都是加一个文件。
4. **粘性 key 含筛选条件**：同 session 但换了业务条件，不该硬复用旧代理。

## 踩坑记录

- **坑 1**：`_measure_latency` 一度在 async 函数里混用 `run_until_complete` → 会死锁。
  改为纯 async 方法直接 await。
- **坑 2**：API 里把 `_http_conf` 误写 `_get_conf` → 运行时 NameError。写完即跑测试发现。
- **坑 3**：random 策略透传全部 params 给 service.get，而 session 参数 service.get 不认。
  改为只透传 service.get 认识的参数。
- **坑 4**：探针导致测试联网 → 加 `probe_safety` 开关，测试构造关闭。
