# 阶段 00：工程规范初始化

## 背景思考

proxy-pool 是一个从零自研的代理池项目，当前仓库几乎是空的（只有一行 README）。
项目初期最容易发生的问题：每个 agent 会话上下文丢失、提交随意、进度不可查、坏代码漏进主干。

仓库旁 `../engineering-discipline` 正好是一套现成的、与语言无关的工程纪律模板
（AGENTS.md + 阶段文档 + PROGRESS.md + stage 提交 + CI）。
本阶段目标：把这份规范完整引入 proxy-pool，让后续所有阶段都按统一节奏推进。

## 完成内容

- 复制并定制 `AGENTS.md`（项目手册：背景/命令/纪律/提交规范/当前阶段）
- 建立 `docs/PROGRESS.md`（进度总索引，含阶段总览表）
- 复制阶段文档模板 `docs/01-阶段模板.md`
- 建立 `.github/workflows/ci.yml`（ruff lint + pytest + commit-lint）
- 安装 skill 到 `.opencode/skills/engineering-discipline.md`，后续 agent 可直接加载
- 新增 `.gitignore`（Python/venv/缓存/日志）

## 技术决策及理由

- 采用 `../engineering-discipline` 作为规范来源，不重新发明：它已沉淀了阶段化推进、
  Conventional Commits、CI 兜底三块经验，且与语言无关，直接复用成本最低。
- CI 只保留 Python 后端 job（本仓库无前端），按 `ruff` + `pytest` 裁剪模板。
- `AGENTS.md` 保留了模板的"工程纪律约定 / Git 提交规范"两节核心，其余按本仓库实际填写。

## 实际命令

```bash
# 复制 skill（供 agent 加载）
mkdir -p .opencode/skills
cp ../engineering-discipline/SKILL.md .opencode/skills/engineering-discipline.md

# 验证
git status
ruff check .   # 当前无代码，应无报错
```
