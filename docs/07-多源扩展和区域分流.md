# 阶段 07：多源扩展 + 自动扫描 + 区域分流验证

## 背景思考

用户指出核心问题：源太少、且现有源（geonode/scdn）多是国外代理，配上"验证 baidu"
导致**几乎一个能用的都没有**。提出两件事：
1. 多源多多益善，**国内国外都要**，别在一开始就砍源。
2. 国外代理连不上 baidu 不代表它用处——应该**按区域分流验证**（国内测 baidu、国外测 youtube）。
3. 还提醒：本机走香港代理，验证结果代表"海外视角"；将来池子在国内跑还要考虑
   国内可达性（这个先记着，暂不实现）。

## 完成内容

- `fetcher/sources/proxifly.py`：新源，全球免费代理 JSON API
  - **全量接入不做预筛**（没有只取 CN），国内国外都 yield。
  - yield **Proxy 对象**（不只字符串）：带上 region（geolocation.country）、https、anonymous。
- `fetcher/manager.py`：
  - **自动扫描 sources/ 目录**发现所有源（importlib），加新源只需放文件、不用改代码。
  - 支持 fetch() yield **字符串或 Proxy 对象**（知道 region 的源带信息）。
- `helper/check.py`：**按区域分流验证目标**
  - `REGION_TARGETS`：CN → baidu/qq；GLOBAL（其它/未知）→ youtube。
  - `_targets_for(proxy)`：按 `proxy.region == "CN"` 选目标。
  - 同步/异步验证路径都改用区域目标。

## 技术决策及理由

- **不预筛源，全量收 + 验证分流**：源的价值是"多一点候选，多多益善"；
  筛选交给"区域标签 + API 按需筛"（后面做）。这比在采集时砍源更合理——
  国外代理对需要国外访问的用户是有用的，不能因为我们要 baidu 就丢掉。
- **自动扫描源目录**：源数量会持续增加，手动在 manager 里列已不现实；
  用 importlib 扫描 `sources/`，任何 `BaseFetcher` 子类且 `enabled` 自动被发现。
- **区域分流而不是单目标**：单一 baidu 目标会让"国外代理"全部误判为死。
  按 proxy.region 选对目标，区域不对口才失败，而不是代理本身死了。

## 踩坑记录

- 坑 1：proxifly 数据里代理的 ip/port 是分开字段，而 HTML 类源（66daili 等）是
  ip 和 port 分单元格、且配字符串连在一起，`parse_proxies_from_text` 的 `ip:port`
  正则对**分单元格的 HTML** 不适用（0 命中）。所以表格类源要单独按列解析，
  不能复用纯文本正则。本次先落地 JSON/纯文本类源。
- 坑 2：proxifly 的 CN 代理实测 24 个全连不上 baidu——再次印证免费代理存活率极低，
  与"多源 + 多批次"才能稳定抓到活的。
- 坑 3：manager 从"手动 source 列表"改成自动扫描后，首个已验证（自动发现 proxifly+scdn），
  geonode 某次抓取失败没出现——单源失败不影响其它，符合预期。
