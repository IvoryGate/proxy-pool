# 阶段 03：验证器（格式 / http / https / 淘汰）

## 背景思考

代理抓到后不能直接信——免费代理存活率极低（实测 10 里 1 个可用都算好）。
需要一层"质检车间"：决定代理能不能进池、何时淘汰。
同时要回答用户"校验单只测百度是不是不够、国外怎么办"的疑问，
把验证从"单目标存活"做成"多能力分层"。

## 完成内容

- `helper/check.py` 的 `Checker`：
  - **格式校验** `_format_check`：正则判 `ip:port` 是否合法，不合法直接判失败，
    连网络请求都不用发。
  - **http 校验**：通过代理访问 `HTTP_URL`（默认 baidu.com），拿到 200 → 可用。
  - **https 校验**：http 过了才验（访问 `HTTPS_URL`，默认 qq.com），结果写回 `proxy.https`。
  - **淘汰计数**：成功 → fail_count 归零；失败 → fail_count+1；
    超过 `MAX_FAIL_COUNT`(3) → 判定淘汰。
  - **目标可配置**：`HTTP_URL`/`HTTPS_URL` 可在构建时传入，想换目标（如国外站）改配置即可。
- `tests/test_check.py`：淘汰逻辑、成功清零、格式拒绝、https 标记 等测试（用假验证器避免联网）。

## 技术决策及理由

- **http / https 分层**：http 才是"代理活着"的核心，https 是"能力"。
  先验 http，过了才验 https，避免无谓请求；https 结果决定代理能否用于加密场景。
- **文件格式校验放最前**：防止"垃圾格式"白白消耗网络请求和时间。
- **过滤目标做成构造参数**：默认国内存活（baidu/qq），但用户可能想测国外
  ——不写死，构造函数注入。也方便测试注入假 url。

## 实际命令

```bash
.venv/bin/python tests/test_check.py   # → ALL PASSED
```

## 踩坑记录

- 坑 1：http 校验里 `proxies` 参数在 httpx 0.28 改成了 `proxy`（单字符串而非 dict）→
  参考实现用的是老 API，我们这边适配新 API（`learn/02` 记过）。
- 坑 2：加了 https 后，原来只覆写 `_http_check` 的假验证器会真发 https 请求变得慢/不稳。
  后来给假验证器补了 `_https_check` 覆写，测试才稳定。
