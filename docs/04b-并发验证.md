# 阶段 04b：并发验证（asyncio + httpx）

## 背景思考

顺序验证代理非常慢：每个代理最多等 5 秒超时，100 个最坏要 500 秒。
验证过程大部分时间在"等网络"（I/O 等待），CPU 是闲置的——这正是异步的用武之地。
希望通过 asyncio 让验证从"一个个等"变成"一起等"，总耗时 ≈ 最慢那个。

## 完成内容

- `learn/03_并发验证.py`：教学脚本 —— 对比顺序 vs 并发，
  并用假延时实证：10 个任务各延时 2 秒，顺序约 20s、并发实测 2s。
- `helper/check.py` 的 `Checker` 增加：
  - `check_all(proxies)`：**异步并发批量验证**入口（用 `asyncio.run` 包一次跑完）。
  - `_check_all_async` + `_check_one_async` + `_async_fetch_ok`：内部用
    `httpx.AsyncClient` + `asyncio.gather` 并发处理整批，逐个更新代理状态。
  - 保留原同步 `check()`/`_http_check` 等（测试和单代理场景仍友好）。
- `tests/test_check.py`：用假异步验证器测 `check_all` 的并发返回结构 + 状态更新。

## 技术决策及理由

- **用 asyncio 而不是多线程**：验证是重度 I/O 场景，asyncio 单线程协程
  就能把"等网络"的时间让给别的请求，开销比开一堆线程小、代码也更清晰。
- **`httpx.AsyncClient` 复用连接**：不要每个代理 new 一个 client，
  复用同一个（`async with ... as client`），避免重复握手开销。踩过的坑。
- **同步 check() 保留**：测试和"单个代理"场景不需要引入异步，保留两套入口。

## 实际命令

```bash
PYTHONPATH=. .venv/bin/python learn/03_并发验证.py async   # 看并发效果
.venv/bin/python tests/test_check.py                      # → ALL PASSED
```

## 踩坑记录

- 坑 1：httpx 0.28 里 `AsyncClient().get()` 每代理 new 一个 client 开销大 →
  改为共用 client 传入每个任务。
- 坑 2：第一次写错 `sync_check` 引用（应为 `sync_verify`），且留了无用占位代码 →
  清理修正。
- 坑 3（用户提的）：验证只测 baidu 只能说明"国内可存活"，国外未知。
  已在 03 阶段把验证目标做成可配置，以后想测国外改 `HTTP_URL` 即可。
