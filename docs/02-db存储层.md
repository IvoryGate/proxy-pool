# 阶段 02：db 存储层 RedisPool

## 背景思考

Proxy 模型 + Redis 入门打通后，发现"每次都要手写 hset/hget/hkeys 那些裸命令"
太散：爬取、验证、API 三处都会操作 Redis，如果到处裸写，代码重复、还容易写错。
想到要做一层封装，把"存/取/随机取/删/统计"包装成语义化方法。

## 完成内容

- `db/redis_client.py`：`RedisPool` 类
  - `put` 存代理 / `get` 随机取（可指定 https）/ `pop` 取并删 / `delete` 删
  - `getAll` / `count` / `clear` / `exists`
  - **https 辅助 set 自动维护**：存 https 代理时同时 `sadd` 进 `use_proxy:https`，
    取 https 代理时只从 set 里 `srandmember`，不用全表扫。
- `tests/test_redis_client.py`：count / get(https) / pop / getAll 过滤 四项测试。

## 技术决策及理由

- **主表 hash + 辅助 set 双结构**：为什么不用单个 hash？
  因为"取 https 代理"若只靠 hash 得全量 `hvals` 后 Python 过滤（O(n) 扫描）。
  加一个 set 专门存 https 名单，取用变 O(1)。这是"冗余索引换速度"的取舍。
- **封装为类而不是散函数**：state（连接、表名）和内聚的方法放一起，
  上层只跟 `RedisPool` 打交道。
- **随机取兼容老 Redis**：本机 Redis 6.0 没有 `HRANDFIELD`，用 `HKEYS`+`random.choice`。

## 实际命令

```bash
.venv/bin/python tests/test_redis_client.py   # → ALL PASSED
```

  `__main__` 调不到 → 修正后通过。
